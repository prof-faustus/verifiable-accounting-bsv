# Reproducibility

Every reported value in this project is produced by running the code and is
regenerated by `reproduce`. No value, number, benchmark, or chain fixture is
invented.

## Commands

```
npm ci            # install with the pinned lockfile
npm run build     # strict type-check + compile
npm run lint      # format check + forbidden-token scan
npm test          # full test suite
npm run reproduce # regenerate every deterministic vector + diff against committed
npm run study:store     # storage / retrieval study, CI point
npm run study:assurance # assurance study, CI point
```

`reproduce` regenerates and diffs:

- the genuine BSV block Merkle vector, `vectors/merkle/bsv_block_v1.json`
  (block hash, ordered txids, expected merkle root; the vector carries a BSV
  `source` field — it is genuine data, never fabricated);
- the storage-study CI point, `vectors/study/storage_<N>.json`;
- the assurance-study CI point, `vectors/study/simstudy_<M>.json`.

It exits non-zero on any mismatch.

## CI point vs full run

The studies run a small **CI point** in CI (deterministic, byte-stable JSON that
`reproduce` diffs). The larger **report points** (storage N ∈ {1024, 16384,
262144}; assurance M up to 100000) are run on demand and print machine-readable
lines.

- Storage study seed and points: see `packages/simstore`.
- Assurance study seed and points: see `packages/simstudy`.
- Predetermined level rule for the studies:
  `k = max(1, min(height − 1, floor(log2(N) / 2)))`, recorded in each study's
  output.

## Local-timing note

Absolute timings (verification time, proof generation/verification time) are
**local** measurements. They are labelled `local` in the study output and must be
re-run on the reporting hardware to be quoted. The deterministic vectors and
counts (byte sizes, detected/missed fault counts, roots) are **not** timing
dependent and reproduce byte-for-byte on any conforming machine.

### Reporting hardware

When quoting absolute timings, record the machine here, e.g.:

```
CPU:    <model>
Memory: <size>
OS:     <name/version>
Node:   24.x
```

Timings produced on any other machine are indicative only.
